# Glossary

This file is the authority on domain terms. Code, prompts, logs, and documents use these words with these meanings. One concept has one term. One term has one meaning.

Only the repository owner changes this file. An agent edits it only when the owner asked for that change or approved it beforehand. Otherwise the agent stops and asks. Do not edit this file to match code that drifted.

A code name is one type, table, column, or function. A code name that needs a condition, such as "row with role X" or "field when Y", names a subset of something unnamed. Name the thing.

## Work

| Term | Meaning | Code name | Do not say |
|---|---|---|---|
| workflow | One request, from its first event to done, cancelled, or failed. | `WorkflowState` | |
| workflow definition | A named set of stages in config. A workflow runs one. | `WorkflowDefinition`, `workflows/<name>.yaml` | |
| stage | One step of a workflow. It produces one artifact. Config declares it. | `Stage` | |
| job | The execution of one stage. Its tasks belong to it, and it holds what they produce. | `jobs` row | |
| task | One execution of a role in a job. | `tasks` row | |
| model-call task | A task that runs as model calls through the gateway, with no sandbox and no harness session. | `AuthorActivity.execution "model"`, no sandboxes row | |
| author | The task that produces and revises the artifact of its job. | `TaskRole "author"` | |
| author activity | What the author does in one turn: it produces the artifact or it revises it. Config sets the execution, harness, model, effort, and skill of each activity. | `AuthorActivity`, `Stage.author` | mode, phase, step |
| produce | The author activity that writes the first artifact of a job. | `Stage.author.produce` | write, draft, compose |
| revise | The author activity that changes the artifact after an agent review or feedback. | `Stage.author.revise` | resolve, fix, edit, polish |
| researcher | The task role that runs a research skill in a harness session to extract a research payload. | `TaskRole "researcher"` | |
| research payload | Structured data with file and line references that a researcher task produces. | `jobs.research_payload` | |
| choice ending | A stage completion that requires a selection. | `Stage.ending "choice"` | choice stage |
| selection | The one option a person chose on a stage with a choice ending. | `jobs.selection` | |
| refiner | One configured agent step over the artifact of a stage, before the handover. A reviewer or a polisher. | `RefinerEntry`, `ReviewerEntry`, `StageRefiner` | pass, place |
| refiner index | The position of a refiner in the list of its stage. Reviewers come first, then polishers. | `refiner_index` | place |
| refiner run | One execution of a refiner on an artifact. | `tasks` row with role `reviewer` or `polisher` | pass task, the review |
| run number | Which execution of the same refiner on the same artifact this is, from 1. | `runNumberOf`, `phaseRunOf` | round |
| generation | The sandbox start count of a task. It drops alarms and connections of an older sandbox. | `sandboxes.generation` | version, revision |
| restart | A task starting over in a fresh sandbox on its branch after a failure it may recover from. A task restarts at most twice, then fails. | `sandboxes.restarts` | retry, rehydrate |
| workflow repo token | The code host token a task's sandbox uses for the workflow's repository. An author's token may push. A reviewer's token has only the permissions its artifact kind allows. It is refreshed before it expires. | `mintWorkflowRepoToken`, `SandboxStartSpec.workflow_repo_token` | task token, task credential |
| all-repos read token | A read-only code host token for every repository the code host credential reaches. A sandbox gets one only when `read_all_repos` is on. Git uses it for every repository except the workflow's. | `mintAllReposReadToken`, `SandboxStartSpec.all_repos_read_token` | read token, read credential |
| segment | Consecutive reviewers that settle together. A judge or the end of the list ends it. | `segmentStartOf`, `endsSegment` | |
| phase | A group of refiners on the board. Agent review, then polish. | `RefinerPhase` | |
| milestone | A delivery slice in a plan document. | plan skill text | phase |
| page parent | Where the document host puts the pages of a workflow. The plan names it, the way it names the repository. On a host that nests pages, it is the page or database that holds the root page, and a request that names none gets the default from the workflow definition. On a host that does not, it is the tracker project of the issue, or the agent asks. | `WorkflowState.page_parent`, `set_plan page_parent`, `documents.page_parent` in the workflow definition | docs.parent, folder |
| root page | The page a person reads first, on a document host that nests pages. It is the page of the stage that `documents.root_page` names in the workflow definition. It starts as an empty container and holds every other page of the workflow, as a subpage or as a link. | `documents.root_page` in the workflow definition, `WorkflowState.root_page` | root stage |
| resources section | The last section of the root page. It lists the subpages and the linked pages. Code writes it, and an author never changes it. | `RESOURCES_HEADING` | |

## Artifacts

| Term | Meaning | Code name | Do not say |
|---|---|---|---|
| artifact | A pull request, page, issue, or issue set. A job works from one and produces one. | `ArtifactRef`, `artifacts` row | |
| input artifact | The artifact a task works from. | `jobs.issue_id` when the input is an issue, `jobs.input_ref` when the input is an artifact no job of the workflow produced | |
| output artifact | The artifact a task produces. The refiners run on it, and the handover delivers it. | `artifacts` row | |
| revision | The identifier the host gives the current content of an artifact. Null when the host cannot say. | `ReviewSupport.revision` | version |
| handover | The artifact reaches the humans. A changed revision is handed over again. | `markArtifactReady`, `delivered_to_humans_at` | review loop closed |
| follow-up | Work the author does on an artifact after its first handover, at the request of the humans or the host. It starts when a prompt reaches the idle author while the humans hold the artifact. | `startFollowUp`, `delivered_to_humans_at` | revision round |
| feedback | Anything anyone posts on an artifact that the system must route. A review or a comment. | `Feedback` | |
| review | What a person or an agent posts on an artifact as a whole: a summary, findings, and whether it blocks. | `Review`, the review arm of `tasks.result` | verdict |
| ruling | What a judge files on an artifact: approved, or rejected with a reason. Code reads it from a conclusion, or a person gives it. | `Ruling`, the ruling arm of `tasks.result` | verdict |
| comment | Feedback that is not a review. | part of `Feedback` | |
| held comment | A person's comment on a page artifact that the system has not acknowledged. A comment there that mentions the bot, or a request in the chat thread, sends every held comment to the author as one feedback. | `HeldComment`, `Documents.heldComments` | |
| finding | One item in a review or a comment. It may name a location. | `Finding` | |
| agent review | The phase in which the reviewers run. | `RefinerPhase "review"` | review loop |
| findings reviewer | A reviewer that posts a review for the author to weigh. | `mode: "findings"` | feedback entry |
| judge | A reviewer that approves or rejects and posts nothing. It runs once on an artifact. | `JudgeEntry` | |
| conclusion | The closing text of a judge run. | judge prompt | |
| polisher | A refiner that changes the artifact in place. | `TaskRole "polisher"` | |
| gave up | A task or a refiner run whose closing text says it could not do its work or stopped before it finished. It restarts while it has restarts left, then fails. | `harnessGaveUp` | |
| review again decision | The decision, over a model-call author's closing text, that its revision needs the reviewers to run again. A harness author does not get one. The orchestrator agent routes its closing text. | `authorAskedForReview` | |
| option | A proposed direction an author lists under the options heading of a page artifact. | parsed from the page text, not stored | |

## Communication

| Term | Meaning | Code name | Do not say |
|---|---|---|---|
| board | The status message of one job in one chat thread. | `boards` row | |
| checklist | The checkbox lines of a board: the todo list, the follow-up line, the phase lines, and the handover line. | `checklistLines` | |
| todo list | The latest plan entries the harness reported. Replaced whole, frozen at the first artifact. | `TodoSnapshot` | checklist |
| board note | One line from the orchestrator on a board. | `BoardInput.note` | note |
| agent note | A system message to the orchestrator agent. | `noteMessage`, `Applied.notes` | note |
| harness session | The ACP session of one task. | `sandboxes.session_id` | session |
| MCP server | A tool server a harness session connects to. Each provider supplies an MCP server or a CLI, and the deployment config lists the customer's own. | `McpServer`, `mcp_servers` | integration, tool server |
| tracker session | The agent session of the tracker that a reply goes to. | `tracker_session` | session |
| job session | The tracker session on the job's issue, else the workflow's starting session. | `jobSessionOf` | home |
| stop | A person's request in a job session to end the current prompt turn of the job's author. The orchestrator sends the author's harness session a cancel. The task, the job, and the workflow keep running, and the orchestrator does not post anything. | `EventKind "stop"` | cancel, interrupt, pause |
| synced thread | The chat thread that the tracker mirrors as the comment thread of one issue, both ways. It is the first issue a job of the workflow works on. Every later issue gets a link to the thread. | `Tracker.syncChatThread` | mirror, bridge |
| acknowledgement | How a chat thread shows a person that their message arrived. The thread enters its working status when the workflow takes the message. When that takes longer than a few seconds, the message gets the eyes reaction until the working status appears. | `Acknowledge`, `Notifier.acknowledge`, `deliverWithChatAck` | receipt |
| person | One human actor. | `Actor` | |
| the humans | The people a workflow reports to. | | |
| access | Who is authorized to give the deployment work. A tracker or chat user is authorized as a member of the team set for that app. A code host user is authorized when they may push to the repository. The deployment ignores what an unauthorized user writes. | `Access`, `resolveActor` | |
| team | The group whose members `access` authorizes: one tracker team, one chat workspace. An app without a team authorizes every user who reaches the bot. | `access.tracker_team`, `access.chat_team` | |
| screen | The decision by the decisions model that text from outside the deployment may enter a model request. Text that fails, or that the screen cannot check, is quarantined, and code writes a fixed line in its place. | `screenText`, `Screened` | |

## Orchestrator agent

| Term | Meaning | Code name | Do not say |
|---|---|---|---|
| inbox | The events that wait for the next agent turn. | `agent_inbox` | |
| wake | How strongly an event asks for an agent turn. | `Wake` | |
| context | Everything one model request of the orchestrator agent holds: the system prompt, the tool set, and the transcript. | arguments of `generateSteps` | context window, history |
| system prompt | The part of the context that states the role, the stages, the rule blocks, and the current state. Rebuilt for each model request. Never stored. | `systemPrompt` | |
| tool set | The tools the context offers the model. Rebuilt for each agent turn. Never stored. | `loadTools` | |
| rule block | One set of rules in the system prompt, with the tools that leave the request when the block is left out. | `RuleBlock` | |
| active tools | The tools the agent can call in one model pass. | `activeToolNames` | |
| withheld tool | A tool in the tool set that is not active in this model pass. | | |
| unprompted turn | An agent turn where nobody wrote since the last turn. The agent speaks through a tool or not at all. | `TurnFacts.personWrote` false | |
| owed reply | What the message of a person is owed at the end of the turn: an answer in words, or the board alone. | `OwedReply` | reply need |
| requests work | Whether the message of a person requests work. The decisions model says. A message that does not request work leaves the plan, runtime, and context rule blocks out of the system prompt. | `TurnFacts.requestsWork` | intent, classification, asks work |
| requested runtime | The harness and model a person's message names for the work, resolved to a model the harness runs. It replaces the stage's pair for the author of the job it starts. | `RequestedRuntime` | |
| closing text | The text the model ends a turn with. It is posted only as the answer to a person who wrote. | `ModelPass.text` | |
| transcript | The stored conversation of the orchestrator agent. The only part of the context that persists across agent turns. | `transcript` table, `TranscriptStore` | history, memory |
| transcript row | One model message in the transcript, with its id. | `TranscriptRow` | |
| decisions model | The System One model that answers yes-or-no and choice questions with probabilities. The deployment names one, or an ordered list, on its gateway. | `orchestrator.decisions_model`, `Decisions` | classifier, Jev |
| summarization | A single model call that shortens text for its next reader. Compaction, a condensed result, and a digest summary each use one. One model setting serves all of them. | `runPrompt`, `orchestrator.summarization` | |
| compaction | The summarization of the older transcript rows into one recap. It changes the transcript and no other part of the context. | `compactIfLarge`, `replaceThrough` | segmenting |
| recap | The one message that compaction writes in place of the rows it removed. | `RECAP_MARKER`, `COMPACT_PROMPT` | summary |
| condensed result | A tool result that passed `context_tokens` and was replaced by its summarization, with a marker that says so. The model and the transcript hold the same text. | `condensingTools` | clipped, truncated |
| chat history | Earlier messages of the chat channel a request came from. The agent reads it with a tool. It is not part of the transcript. | `historyTools` | history, transcript |

## Statuses

| Status | Meaning |
|---|---|
| task `in_review` | The author is idle and its artifact is out. The status says nothing about what the humans do with it. |
| artifact `drafted` | The refiners hold the artifact, or it waits for them. |
| artifact `ready` | The humans have the artifact. |
| artifact `accepted` | The host accepted the artifact, for example a merge. |
| artifact `removed` | The host no longer holds the artifact as work. A pull request closed without a merge, or a deleted page. |
| workflow `planning` | The agent has the request and no task has started. It has no tie to the `plan` stage. |
