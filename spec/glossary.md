# Glossary

This file is the authority on domain terms. Code, prompts, logs, and documents use these words with these meanings. One concept has one term. One term has one meaning.

Only the repository owner changes this file. An agent edits it only when the owner asked for that change or approved it beforehand. Otherwise the agent stops and asks. Do not edit this file to match code that drifted.

A code name is one type, table, column, or function. A code name that needs a condition, such as "row with role X" or "field when Y", names a subset of something unnamed. Name the thing.

## Work

| Term | Meaning | Code name | Do not say |
|---|---|---|---|
| workflow | A workstream that a person requests in a conversation or a tracker session. It runs one workflow definition and works on the issues of its subject, and on the pull requests and pages they need. It starts when the agent sets a plan that names a definition. It runs until done, cancelled, or failed. | `WorkflowState`, `WorkflowState.definition` | |
| workflow end | The end of a workflow as done, failed or cancelled. The workflow state records it before the first cancel. It cancels the unfinished tasks, writes the status, posts the end and moves the tracker issues of a done workflow. A restart during it does not drop it. The start step arms an alarm that goes on with it. While it runs, the workflow refuses a plan, a job start, another end and a cancel. | `workflow_end`, `endWorkflow`, `resumeWorkflowEnd` | |
| subject | The one issue or tracker project a workflow works on. A tracker origin sets it, else the plan, else the breakdown output. It never changes. An issue subject covers the issue and its direct sub-issues. A project subject covers the project's issues. | `WorkflowState.subject` | binding, scope, root issue |
| workflow definition | A named set of stages in config. A deployment may hold several. A workflow runs the one its plan names. | `WorkflowDefinition`, `workflows/<name>.yaml`, `set_plan` `definition` | |
| stage | One step of a workflow. It produces one artifact. Config declares it. | `Stage` | |
| job | The execution of one stage. Its tasks belong to it, and it holds what they produce. | `jobs` row | |
| job slot | One job a workflow may run at a time. The plan sets the number of job slots. | `WorkflowState.concurrency`, `set_plan` `concurrency` | task slot, concurrency slot |
| task | One execution of a role in a job. | `tasks` row | |
| paused task | A task held by a person or the agent. It keeps its queued prompts and takes none until it resumes. | `tasks.paused_at`, `pauseTask`, `resumeTask` | |
| model-call task | A task that runs as model calls through the gateway, with no sandbox and no harness session. Its task status is `working` from the start of a turn until its page waits in review. A model turn is in flight while it is `working`, except after a stop ended its first turn before the page existed. | `AuthorActivity.execution "model"`, no sandboxes row | |
| model turn | One turn of a model-call task: its model call and the page write that applies the answer. It is in flight from its start until the task records the answer, drops it, or loses it. The task stores the id of the turn in flight. A task that restarts after an instance restart lost its turn holds a new id until its run-again alarm runs the turn again or a stop ends it. | `tasks.model_turn_id`, `startModelTurn` | |
| author | The task that produces and revises the artifact of its job. | `TaskRole "author"` | |
| author activity | What the author does in one turn: it produces the artifact or it revises it. Config sets the execution, harness, model, effort, and skill of each activity. | `AuthorActivity`, `Stage.author` | mode, phase, step |
| produce | The author activity that writes the first artifact of a job. | `Stage.author.produce` | write, draft, compose |
| revise | The author activity that changes the artifact after an agent review or feedback. | `Stage.author.revise` | resolve, fix, edit, polish |
| researcher | The task role that runs a research skill in a harness session to extract a research payload. | `TaskRole "researcher"` | |
| research payload | Structured data with file and line references that a researcher task produces. | `jobs.research_payload` | |
| choice ending | A stage completion that requires a selection. | `Stage.ending "choice"` | choice stage |
| selection | The one option a person chose on a stage with a choice ending. | `jobs.selection` | |
| acceptance check | The decisions call that reads acceptance or the chosen option. A failed call keeps the job open. | `humansAccepted`, `humansSelected` | |
| refiner | One configured agent step over the artifact of a stage, before the handover. A reviewer or a polisher. | `RefinerEntry`, `ReviewerEntry`, `StageRefiner` | pass, place |
| refiner index | The position of a refiner in the list of its stage. Reviewers come first, then polishers. | `refiner_index` | place |
| refiner run | One execution of a refiner on an artifact. | `tasks` row with role `reviewer` or `polisher` | pass task, the review |
| run number | Which execution of the same refiner on the same artifact this is, from 1. | `runNumberOf`, `phaseRunOf` | round |
| generation | The number of the task's current sandbox life. A sandbox start begins the next one, and a stop ends the current one. It drops alarms, connections and awaited calls of an older one. | `sandboxes.generation` | version, revision |
| restart | A task starting over after a failure it may recover from: a harness task in a fresh sandbox on its branch, a model-call task by running its lost model turn again. A task restarts at most twice, then fails. | `tasks.restarts` | retry, rehydrate |
| lost turn | A turn that a restart of the Durable Object cut off before its result was recorded. An agent turn resumes with an agent note, also on a finished workflow when it took a person's message. A harness turn is recovered by a restart of its sandbox. A model turn runs again. | `resumeLostTurn`, `recoverLostTurn`, `resumeLostModelTurns` | dropped turn, orphaned turn |
| instance restart | A new Durable Object instance taking over a workflow. It loses the calls in flight and keeps the store. Distinct from restart, a task starting over. | `onStart` | |
| provision alarm | The alarm that starts a queued task: its sandbox, or the model turn of a model-call author. A job start arms it right after it writes the task, before any router write. An instance restart arms it again for every unpaused queued task. | `provision`, `provisionQueuedTasks` | |
| task end alarm | The alarm the end of a task arms right after it writes the status, whether the task completed, was cancelled or failed. It names the task, and the reason of a cancel or a failure. The teardown cancels it once its last call returns: the destroy of the sandbox, and the failure post of a failed researcher or author. When an instance restart cuts the teardown, the alarm runs it again. For a completed task it only destroys the sandbox again. While the teardown still runs, the alarm is armed again instead. | `resumeTaskEnd`, `TaskEndAlarm` | |
| workflow repo token | The code host token a task's sandbox uses for the workflow's repository. An author's token may push. A reviewer's token has only the permissions its artifact kind allows. It is refreshed before it expires. | `mintWorkflowRepoToken`, `SandboxStartSpec.workflow_repo_token` | task token, task credential |
| all-repos read token | A read-only code host token for every repository the code host credential reaches. A sandbox gets one only when `read_all_repos` is on. Git uses it for every repository except the workflow's. | `mintAllReposReadToken`, `SandboxStartSpec.all_repos_read_token` | read token, read credential |
| segment | Consecutive reviewers that settle together. A judge or the end of the list ends it. | `segmentStartOf`, `endsSegment` | |
| phase | A group of refiners on the board. Agent review, then polish. | `RefinerPhase` | |
| milestone | A delivery slice in a plan document. | plan skill text | phase |
| page parent | Where the document host puts the pages of a workflow. The plan names it, the way it names the repository. On a host that nests pages, it is the page or database that holds the root page, and a request that names none gets the default from the workflow definition. On a host that does not, it is the tracker project of the issue, or the agent asks. | `WorkflowState.page_parent`, `set_plan page_parent`, `documents.page_parent` in the workflow definition | docs.parent, folder |
| root page | The page a person reads first, on a document host that nests pages. It is the page of the stage that `documents.root_page` names in the workflow definition. It starts as an empty container and holds every other page of the workflow, as a subpage or as a link. | `documents.root_page` in the workflow definition, `WorkflowState.root_page` | root stage |
| resources section | The last section of the root page. It lists the subpages and the linked pages. Code writes it, and an author never changes it. | `RESOURCES_HEADING` | |

|---|---|---|---|
| artifact | A pull request, page, issue, or tracker project. A job works from one and produces one. | `ArtifactRef`, `artifacts` row | |
| input artifact | The artifact a task works from. | `jobs.issue_id` when the input is an issue, `jobs.input_ref` when the input is an artifact no job of the workflow produced | |

| follow-up | Work the author does on an artifact after its first handover, at the request of the humans or the host. It starts when a prompt reaches the idle author while the humans hold the artifact. | `startFollowUp`, `delivered_to_humans_at` | revision round |
| feedback | Anything anyone posts on an artifact that the system must route. A review or a comment. | `Feedback` | |
| routing decision | Where one feedback on a running workflow goes: to the author as a prompt, to nobody because it asks for nothing, or to the agent, which tells the humans. A decisions call that fails reads as the agent. A feedback gets one routing decision across all its deliveries. The workflow marks the feedback seen with its routing decision. | `FeedbackRoute`, `feedbackRouteFrom` | |
| review | What a person or an agent posts on an artifact as a whole: a summary, findings, and whether it blocks. | `Review`, `reviews` | verdict |
| review read | The read of the review a findings reviewer filed on the host, at its turn end. It finds a review, does not find one, or fails. A read that does not find a review counts as clean. A read that fails hands the artifact over blocked. | `ReviewRead`, `postedReview` | review lookup |
| ruling | What a judge files on an artifact: approved, or rejected with a reason. Code reads it from a conclusion, or a person gives it. | `Ruling`, `rulings` | verdict |
| ruling ask | The agent being told to get a person's ruling on a judge run that the decisions model could not rule. It stays on the judge run until a ruling replaces it. | the `asked` arm of `RulingState` | |
| comment | Feedback that is not a review. | part of `Feedback` | |
| comment thread | A page comment and the replies under it. | `commentThread` | discussion |
| held comment | A person's comment on a page artifact that the system has not acknowledged. Three things send every held comment to the author and acknowledge it: a comment there that mentions the bot when the decisions model routes it to the author, a person's message that asks for a revision, and any prompt the orchestrator sends to that author. The author gets only the held comments the host marked read. A held comment the screen does not admit, the host does not mark read, or a mention routes elsewhere stays held. | `HeldComment`, `Documents.heldComments` | |
| bare mention | A comment on a page artifact that mentions the bot and says nothing else. With no held comment on the page, the system marks it read and the agent asks the person what they want. With held comments, it sends them as any mention does. | | empty mention |
| finding | One item in a review or a comment. It may name a location and a passage. | `Finding` | |
| passage | The few words of a page that a finding quotes. The page host anchors the finding's comment to the block that holds them. | `Finding.passage` | anchor, quote |
| inline finding | A finding of a page review that code posts as a comment on the block that holds its passage. | `Documents.commentOnPassages` | inline comment |
| outcome comment | The one page comment of a page review. It holds the review line, the summary, how many findings are inline, and every finding without a block. | `pageReviewOutcome` | summary comment |
| page text change | The text an author read from a page and the text it wants the page to hold. The host writes only the parts that differ, so the blocks outside them keep their comments. | `PageTextChange`, `Documents.updatePageContent`, `planPageTextUpdate` | page overwrite |
| comment reply | What the author says in the comment thread of one page comment it was sent: what it changed for the comment, or why the page does not change. The author posts it before it changes the page. It does not resolve the comment thread. | `CommentReply`, `Documents.replyToComment`, `validateCommentReplies` | resolution |
| agent review | The phase in which the reviewers run. | `RefinerPhase "review"` | review loop |
| findings reviewer | A reviewer that files a review for the author to weigh. | `mode: "findings"` | feedback entry |
| judge | A reviewer that approves or rejects and posts nothing. It runs once on an artifact. | `JudgeEntry` | |
| conclusion | The closing text of a judge run. | judge prompt | |
| polisher | A refiner that changes the artifact in place. | `TaskRole "polisher"` | |
| checks gate | The step that holds a pushed revision until its checks pass, wait, go back to the submitter, or block the handover. | `checksGate`, `ChecksGate` | |
| submitter | The task whose push made the current revision. Failed checks or a conflict go back to it. | the `submitter` of `checksGate` | pusher |
| checks send-back | The checks gate giving failed checks or a conflict back to the submitter, at most once per revision. | `claimChecksSendBack`, `sendFailedChecksBack`, `sendConflictBack` | |
| gave up | A task or a refiner run whose closing text says it could not do its work: blocked, without access, stuck on an error, or out of time or budget. It restarts while it has restarts left, then fails. | `harnessGaveUp` | |
| stopped on a limit | A researcher or refiner turn that the harness ended on max tokens, its turn request limit, or a refusal, before the work was complete. It restarts while it has restarts left, then fails. Distinct from stopped early, an author turn that ended on its own. | `UNFINISHED_STOPS` | |
| stopped early | An author turn that ended on its own with the work unfinished, and that does not wait on a person. The author counts as stalled at once. | `AuthorTurnOutcome "stopped_early"` | |
| stalled | An author whose work is unfinished, that does not wait on a person, and that showed no progress for the no-progress limit, or whose turn stopped early. It gets a nudge in the same session. A second stall with no progress since the nudge restarts it in a fresh sandbox, and it fails once its restarts are used up. Progress is a tool call or a todo list change. Text alone is not progress. | `nudgeOrRestartStalledTask`, `sandboxes.nudged` | |
| review again decision | The decision, over a model-call author's closing text, that its revision needs the reviewers to run again. A harness author does not get one. The orchestrator agent routes its closing text. | `authorAskedForReview` | |
| route note | The note that asks the orchestrator agent to route the author's answer to a findings review, with `request_review` or `finish_review`. It goes out when the answer settles below the review limit, and again on each checks report while the review waits. | `askAgentToRoute` | |
| review limit | The number of runs, `max_review_runs`, after which the author's answer to a findings reviewer entry moves the list past that entry without another review. | `reviewLimitReached` | |
| recheck alarm | The repeating alarm that reads the checks again while the checks gate waits or sent a revision back. | `recheckChecks`, `RECHECK_SECONDS` | |
| option | A proposed direction an author lists under the options heading of a page artifact. | parsed from the page text, not stored | |

## Statuses

| Status | Meaning |
|---|---|
| task `in_review` | The author is idle and its artifact is out. The status says nothing about what the humans do with it. |
